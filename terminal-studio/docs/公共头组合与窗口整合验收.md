# 公共头组合与窗口整合验收

日期：2026-10-19。工程：`terminal-studio`。

本轮支持在分组内维护多套公共头，再由每条协议选择使用哪些头及拼接顺序。Windows 原生白色标题栏并入工作区标签栏。下列记录区分客户端验证与安装验收。

## 使用步骤

1. 打开“协议管理”，在左侧选择系统下的具体分组。
2. 展开“公共头”，点击“新增公共头”，填写名称与字段；可复制已有头后修改。完成后点击“保存公共头”。
3. 编辑该分组的一条协议，在“使用公共头”中勾选需要的头。通过“前移／后移”调整“拼接顺序”，然后保存协议。
4. 在“交互控制台”选择该协议，展开“公共头”填写参数后发送。点击实际收发记录检查各头与净荷的解析。

例如 A、B 两套公共头可组合为 A、B、A→B、B→A；全部取消表示不使用公共头。头内字段顺序保持原定义，所选头依次拼接在净荷之前。

公共头按分组独立管理，不跨组借用。编辑公共头会影响使用它的协议；正在被协议引用的头不能删除。协议字段若已配置“覆盖公共头”，取消对应头后必须重新选择覆盖目标或取消该覆盖，不能把失效引用悄悄当作净荷发送。同名头字段的覆盖选项显示所属头及序号。

旧协议保留原公共头继承规则，旧头内重复字段名保持兼容。新协议由用户明确勾选；保存为空选择后不会自动恢复旧头。切换分组时，未保存的公共头编辑可以继续编辑、保存后切换或放弃后切换。

窗口右上角提供最小化、最大化／还原、关闭；顶部空白区域用于拖动和双击最大化。报文详情保留窗口控制区。关闭含未保存编辑的窗口或标签页时，需要在应用内确认。

## 候选 EXE 的真实客户端验证

使用客户端导入协议、创建公共头 A、复制为 B、保存头库，再从协议详情分别保存五种选择。通过“发送报文”按钮发送，独立本机 UDP socket 收到并回送以下字节：

| 选择 | 对端实际收到的 HEX |
| --- | --- |
| A | `A1 D1` |
| B | `B1 D2` |
| A→B | `A1 B1 D3` |
| B→A | `B1 A1 D4` |
| 无头 | `D5` |

接收的 A→B 报文在详情中分别显示公共头 A、公共头 B 和净荷；窗口控制仍可见。客户端 XML 导出后重新导入，五种选择及顺序保留。

旧无人机协议通过客户端发送 `0x21` 配置请求，配置条目数为 `02`；独立对端实际返回 `0x22`，两条配置结果均解析为 `AA`。原业务规则未由上述头组合对照数据替换。

候选 EXE 的最大化／还原按钮和顶部空白区域双击已验证。首次窗口关闭检查发现原生确认调用的异步处理问题，已改为应用内确认；最终二进制复测见下节，不把首次检查记作关闭验收通过。
