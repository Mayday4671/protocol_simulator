# 动态设备关联资料

## 配置入口

1. 打开 **设备管理 → 业务资料 → 资料类型**，选择所属系统。
2. 新增类型，例如“电话”“端口”“传感器”；填写属性名称。
3. 选择是否必须关联设备，以及唯一标识范围。
4. 在 **协议管理 → 请求信令 → 应答保存规则** 中选择类型，配置响应、成功条件、唯一标识和所属设备字段。
5. 操作选择“新增或更新资料”时，将请求或应答字段映射到资料属性；选择“删除对应资料”时，只需定位标识与成功条件。

类型按系统管理，同系统多个协议可以复用。同名类型在不同系统中独立。类型只定义资料属性，字段编码、字节长度、解析方式仍由各协议决定。

## 标识与操作

- **同一系统、通道内唯一**：同类型的相同编号定位同一条资料。
- **所属设备内唯一**：以所属设备和资料编号共同定位。例如设备 A 和设备 B 均有端口 01，保存或删除 A 的端口 01 不影响 B。
- **新增或更新**：只更新本规则映射的属性，其他属性保留。
- **删除**：只处理匹配到成功应答的条目；失败、未匹配或超时不删除。删除不存在的条目按已无该资料处理。
- 所属设备必须已存在于同一系统与通道。删除关联资料不删除设备；设备仍有关联资料时，禁止删除设备。

电话使用普通资料类型，不需要专门的电话页面或硬编码协议。新增其他类型也不需要修改程序。

## 查看及后续使用

业务资料可按系统、类型、所属设备筛选。展开记录查看保存属性。

协议字段旁的 **从设备取值** 中，选择设备后，可选设备本身的属性，也可选该设备关联资料的属性。取值会检查编码和长度；选中后填入当前固定值，不是运行时自动更新的绑定。

## 修改与兼容

- 类型名称和属性可以维护。删除仍被规则映射或已存资料使用的属性会显示引用原因，不会静默删除旧值。
- 类型被规则或资料引用时，不允许直接改变设备关联要求和唯一范围；可新建类型，或解除引用后再改。
- 类型仍被规则或资料引用时不允许删除。设备档案是基础类型，保留其入口；其他用户类型可删除。
- 类型定义、操作和保存规则一起随协议 XML 导入导出。旧 XML 缺少新设置时，默认“新增或更新、通道内唯一”；已有自由类型从原规则/资料推导，保持原数据可读。
- 保存等待期间修改协议、规则或类型，会阻止旧应答继续入库，需要重新发送。
- 请求/应答关联、成功值仍由用户按实际协议配置，不会因类型名称或信令名称自动判定业务成功。
