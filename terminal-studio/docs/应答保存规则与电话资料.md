# 应答保存规则与电话资料

## 配置入口

在 **协议管理** 找到请求协议，点击操作列的数据库图标 **应答保存规则**。启用后选择：

1. 对端返回的应答协议。
2. 保存类型：设备档案、电话资料，或者自定义资料类型。
3. 请求与应答中的流水号字段。没有流水号的协议须明确选择单请求模式。
4. 请求资料来源：整条报文，或者一个数组的每条记录。
5. 应答结果：整体结果，或者逐条结果数组。逐条结果可按顺序或标识对应，数量必须一致。
6. 成功结果字段及成功值。成功值必须按业务协议填写，不根据字典顺序推断。
7. 资料唯一标识、可选显示名称，以及需要保存的属性。属性值可以来自本次请求或匹配的应答。

未启用规则的协议只收发和解析，不自动创建业务资料。会话捕获可以更新已有设备，但不再凭会话字段新建设备。

## 设备配置示例

对于请求含“设备列表”、应答含“响应列表”的协议：

- 请求资料选“设备列表”，应答结果选“响应列表”。
- 应答只有结果、没有设备标识时，选择“按顺序”，请求和应答条目数量须相等。
- 成功字段选条目中的“响应结果”；成功值按对端协议填写。
- 唯一标识选条目中的“设备地址”。
- 添加设备地址、序列号、IP、端口等保存属性，逐个选择来源字段。

只有成功的条目写入设备档案。相同通道、系统和设备标识更新原档案；未在本次规则映射中的已有属性保持不变。

本次升级没有替用户当前协议指定成功码或绑定字段，需按实际业务配置。

## 电话资料

保存类型选择“电话资料”，唯一标识可选择电话号码，**所属设备标识**选择请求中的设备地址字段。它须与同一通道、同一系统内已有设备的唯一标识一致。

电话号码等属性由保存映射配置，不限于固定几项。成功后在 **设备管理 → 业务资料** 查看，展开记录查看属性及所属设备。设备仍有关联资料时不能删除；应先删除关联资料。

其他业务可使用自定义类型，同样配置唯一标识和属性；关联设备为可选项。

## 匹配与限制

- 只处理已实际发送请求的快照，匹配通道、系统、对端 IP/端口、应答协议及流水号。
- 已使用的流水号在本次监听期间不能再次用于保存请求，避免旧应答误关联；关闭监听后清理等待状态和流水号缓存。
- 单请求模式在相同通道、对端和应答协议下只允许等待一笔请求。没有流水号的协议无法区分上一笔迟到的重复应答；超时后须重启监听。
- 成功值比较实际报文字节。条目数量不符、标识重复、关联设备不存在、报文不完整等情况拒绝保存；原因写入该报文的解析摘要。
- 请求协议或规则变更后，旧的等待结果不能沿用。协议 XML 导出会携带保存规则及应答协议。
- 当前数组入库支持定长、无嵌套、无子字段条件的条目；界面与后端校验不支持的定义并拒绝错误保存。
