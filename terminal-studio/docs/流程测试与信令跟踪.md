# 流程测试与信令跟踪

## 手动联调

1. 在交互控制台选择协议、通道。
2. 右侧「流程进度」自动显示当前信令对应的流程。唯一匹配时无需再选流程；直接发送首个发送步骤的信令即可开始跟踪。以接收步骤起步时，点击「手动跟踪」提前等待对端。
3. 正常填写字段并发送报文，或者让对端发送。抽屉中的纵向时间轴显示每一步状态和时间。抽屉没有遮罩，可以继续操作发送区；收起不停止测试。
4. 点击时间轴步骤展开本步实际收发和历次执行记录；点击报文打开公共头、净荷、尾部分区解析。关闭解析后返回抽屉。
5. 抽屉中可以选择本通道的运行记录；勾选「跟随当前」时自动滚动到当前等待/执行步骤。未匹配报文不会推进步骤。按 Esc 或右上角箭头收起抽屉。

手动跟踪不发包。等待手动发送、等待接收都使用该步骤的超时设置；准备时间长时请增加超时（最大 300000 毫秒）。停止测试只停止流程任务；停止通道同时停止该通道的流程任务。

## 自动执行

交互控制台的流程抽屉中可直接「自动运行」，使用发送区所选通道和设备。也可以在业务流程中打开流程，点击「测试流程」，选择通道后运行；这里保留完整流程图和交互时序。有逐台遍历步骤时选择设备。未选择设备的单次步骤使用信令配置和步骤覆盖值。被动接收步骤等待对端发送，不产生发送报文。

测试图使用开始时保存的流程快照。切页、关掉再打开测试视图不终止后台测试；重新进入可选择运行记录。只在本次应用会话内保留最近 50 次已结束运行；单次保留最近 2000 条事件，步骤最终状态和已走分支独立保留。重启应用后运行记录不保留，原始报文仍在日志库。

## 应答关联与成功判断

- 默认使用请求和应答中标记为「关联序号」的字段，并反向匹配源/目标设备地址。比对实际编码字节，不读取默认值。
- 字段名不同或关联规则不同，可在步骤属性「应答关联」中选择请求/应答字段对。所有字段对必须一致。
- 无流水号的协议可勾选串行匹配。它按通道、对端和协议匹配，并应用可用的设备地址约束；这类协议本身不能可靠区分同一对端的相同迟到应答，建议协议有序号时使用序号。同一通道只允许运行一个流程测试。
- 发送前的旧应答不会用于新发送；快速应答早于发送日志提交也可关联。
- 「成功判定」可以指定结果字段及成功 HEX 值。未指定时兼容已有规则：配置结果字段的字典首项为成功，无字典时使用 00；无结果字段只表示收到匹配应答，不表示业务操作成功。
- 流程结束不等于全部成功。有失败或超时步骤时，运行显示「有失败 / 超时」。逐台执行中任一设备失败，节点不会因为最后一台成功而变绿。

模板协议可以用明确的匹配正则识别；模板正文不强制转换成字段。字段协议仍要求完整字段布局，避免截断帧推进流程。

- 核心匹配：缺失字段、序号不符、设备地址不符以及显式串行选项。

### 普通发送自动跟踪

修复选了流程但直接发送时进度不变化的问题：发送首个发送步骤的信令前，自动建立手动跟踪，再发出 UDP 报文。无需先点「手动跟踪」，收起抽屉仍继续记录；已有活动运行时复用，完成后再次发送首步开启新记录。不选流程或发送其他信令不会创建观察运行，也不会将旧报文补记为当前步骤成功。首步为接收时仍使用「手动跟踪」提前等待对端。

真实 EXE 的六步直接发送、完成后重新开始、原有自动运行回归通过，详见 `scripts/native_flow_send_tracking.cjs` 和 `docs/superpowers/plans/2026-10-22-flow-send-tracking.md`。

### 请求与响应分别显示

控制台时间轴将配置了期待应答的交互显示为「发送请求」「等待响应」两个节点，计数也为两步。节点状态与事件分别取自实际发送和应答匹配记录；发送完成不等于应答成功。应答被拒绝、超时或停止时，已发送节点保持完成。两侧展开只显示本阶段的记录和报文。无应答的单向发送、独立被动接收各显示一个节点。底层仍使用同一关联事务，保留流水号、地址约束和快速应答边界。

顶部五个选择框统一标签与控件结构，修复通道、设备标签行高造成的错位。此项需要更新客户端，已有六条示例流程无需重新录入。
