# 条目变量编码修复

2026-10-20

## 原因

设备列表的子字段设置了自动流水号。协议编辑器支持该配置，但条目编辑器按子字段定义是否含变量一律拒绝发送；同时生成默认条目时把变量替换成了零。

## 修改

- 保留每条记录的变量默认值，实际手动覆盖以当前条目为准。
- 自动流水号、会话、报文长度和时间戳交给 Rust 在发送时求值。
- 合并数组参数前为每个变量写入子字段声明宽度，避免使用整条记录的宽度。
- 条目界面显示中文取值来源，可切换为固定值。
- 原有数量与单条长度检查继续生效。
- 当前仍只支持定长、无嵌套及无子字段条件的条目；复杂表达式和 ASCII 变量不通过此路径编码，并显示具体字段错误。

## 验证

- `ui_list_variables.cjs`：修复前复现原报错，修复后验证变量默认值、3/4 字节变量宽度及固定值覆盖。
- `ui_dynamic_array_regression.cjs`：条目数量、零条目、非法数量、隐藏编辑、独立分支、计算字段、协议保存通过。
- Rust `array_parameter_variables_keep_each_child_width`：两条 13 字节记录的逐字段字节核对及数量不匹配拒绝通过。
- TypeScript、Vite、Windows EXE 与 NSIS 构建通过。
- 使用用户协议的数据库副本，在独立 `127.0.0.1:49421 → 49422` 通道点击客户端发送：实际收到 43 字节、2 条设备记录；3 字节地址与 4 字节序列号均为本次流水号 1，IP 与端口位置正确。
- 第二次发送把第一条地址改成固定值 `0000AA`：该字段保持固定值，其余流水号字段更新为 2。未修改用户正式数据库。

自动流水号表示当前报文序号，同一报文各条目取值相同，不等同于条目索引。
