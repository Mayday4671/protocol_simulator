# 当前信令自动关联流程

用户要求：选定协议后直接显示对应流程，不再重复选择流程。

设计：从已配置的步骤发送信令、期待响应及触发信令寻找关联。唯一结果直接显示流程名称；多条候选时保留当前关联流程，首次存在歧义才显示候选选择，不任意猜测。运行期间固定当前通道的执行快照，切换同流程的后续信令不重置步骤；切换通道不串记录，结束后恢复随信令显示。未关联的信令显示明确空状态。

- [x] UI 反例：旧版选择协议后不显示对应流程，仍要求手选。
- [x] 当前协议传入跟踪器；唯一匹配自动显示名称，移除重复选择框。
- [x] 多候选范围、响应关联、运行固定、通道隔离、结束释放、未关联空状态及原抽屉回归通过。
- [x] 最终 EXE：不选流程、不点手动跟踪，直接逐条发送完成六步实际 UDP；原自动运行回归。
- [x] 新 NSIS 安装包与验收记录。

验收：`ui_protocol_flow_link.cjs`、`ui_flow_drawer.cjs`、TypeScript、Vite、Windows release 构建通过。隔离客户端的 `native_flow_send_tracking.cjs` 验证不选流程直接发送六步、抽屉收起仍跟踪、结束后再次发送首步建立新运行；`native_iot_walkthrough.cjs` 验证自动与手动各六步、真实 UDP、会话与应答关联、时间轴和字段解析，均通过。
