# 设备档案与工作区设计

用户已同意“手动配置保存 + 配置应答成功后入库，统一设备档案”，并要求一起补齐标签页和字典默认无滚动条；旧测试数据允许清空。

## 设备档案

以 terminal_profiles 为唯一设备信息来源，不再将设备实例作为字典条目维护。字典仅保存枚举。设备唯一身份仍按通道、协议系统、设备 Hex 标识隔离，Session 归属于同一设备。

协议字段新增可选 profile_key（XML 为 profile-key）：明确某字段映射到哪项设备属性；未映射的字段仍属于本次指令。类型码、关联序号、会话和运行时计算字段不能作为普通设备属性保存。不同协议字段可以显示不同名称，但共享同一属性 Key；匹配范围必须在同一协议系统中。

设备管理支持分页列表、搜索、查看、创建、编辑和删除。建档按配置协议呈现已映射字段、必要的条件控制字段、字典选项以及重复列表。固定报文头、尾标和自动变量不挤入设备表单。配置参数与未注册/已注册状态可见；保存普通属性不覆盖并发更新的 Session。

发送侧只带当前设备在当前指令中显式映射的属性。当前指令默认值、设备属性、本次手动覆盖按此顺序合并；身份和 Session 由后端根据选中的设备强制隔离。切换设备或指令后不能复用另一设备的临时值、消息码、业务域或列表内容。设备保存或应答入库后，已打开的管理和控制台页能同步刷新。

## 配置应答入库

配置请求含映射字段，关联的应答声明 result 语义。关联字段增加 correlation 语义，标识请求与应答中的同一流水号。发送时记录限时待确认快照；只有协议系统、通道、应答协议、流水号、设备标识全部匹配且结果成功，才保存该快照。失败、重复、过期、错设备或错协议应答不更新档案；不能回溯“最近一条发送日志”猜测对象。

先支持每个终端的一份配置，可包含多分支、多个附属记录列表；不把普通测点列表误当作独立设备列表。批量独立设备入库若未显式声明映射，不自动猜测。

## 标签页与字典

左侧菜单打开或激活对应页面的标签，同一路径只开一个；支持关闭、邻近标签激活和键盘操作。打开的页面保留实例和独立滚动位置，切换不丢筛选、分支展开状态和未保存的表单。关闭明确丢弃该页面草稿，重要编辑草稿需要确认；无需实现同一路径多实例。

字典左侧仍只到系统/分组二级。右侧折叠卡片按容器高度确定每页数量，折叠默认状态不溢出；展开条目后允许必要滚动。保留字典分页和每张字典条目分页，不能通过 overflow:hidden 截断内容。宽度较小时操作按钮不挤压正文。

## 数据与交付

保留三族复杂 IoT 定义并补充设备属性映射及明确的配置确认。用不同设备信息建出可选择的样例档案，配置值不是对报文头的整表拷贝。先在独立库验证，再对当前应用库在线备份，清理旧测试设备/会话/通信日志并导入新设备数据；保留通道网络地址，协议与字典按新定义更新。清理前核对精确目标与并发状态。更新现有独立 EXE 交付，不生成 ZIP。

## 验收

- 手动建档、编辑、重载后信息一致；复杂分支/列表可填写并保存。
- 选 A / B 设备跨配置、心跳、业务指令发送真实 UDP，各取自己的属性和 Session；当前消息码和业务域保持正确。
- 配置成功应答创建或更新档案，错序号、失败、重复应答不误更新。
- 标签页可见，返回仍有未保存输入，关闭后正常切换。
- 用户截图尺寸与 1366×768 下，折叠字典列表默认无纵向溢出；展开和分页仍可访问全部条目。
