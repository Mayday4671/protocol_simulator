# 多协议与终端隔离修正（2026-09-08）

## 使用方式

1. 协议管理：每行标明公共字段、条件分支或重复分组。展开普通字段也能添加条件和切换编码；子字段支持编码与默认值，保存不再强制 Hex 或清空子字段内容。
2. 设备管理：上方“终端资料与独立会话”选择配置协议，按其字段录入资料。旧序列号字典保留为建议数据。
3. 交互控制台：选择系统、分组、协议、通道和当前终端。终端的源标识与 Session 由所选档案接管。不同列表各自使用前面的有效条目数字段，允许 0 条，超过 200 条明确报错。
4. Session 按通道 + 系统 + 终端标识存储。注册响应自动创建或更新终端档案；重注册后周期任务读取最新会话。旧版节点级混合 Session 不再自动复用，请重新注册。

## 验证

- `npm run build`：TypeScript 与前端生产构建。
- 在 `src-tauri` 运行 `cargo test -p simterm-core`：75 项核心测试，含新增 Hex 10、零列表尾字段、隐藏父分支与 Session 回退回归。
- 在 `src-tauri` 运行 `cargo run --features e2e --bin e2e_isolation`：内存数据库、真实本机 UDP，覆盖 A/B 注册、未注册 C、跨系统同标识、切回 A、重注册后周期发送和停止清理。不会读取或修改正式数据库。
- `scripts/ui_protocol_regression.cjs`：Playwright + Chrome，需可用的 playwright 包，并在 127.0.0.1:1422 启动 Vite。使用隔离 IPC 测试数据，验证双列表、UInt/ASCII 默认值、终端切换、零条目、条件隐藏、动态资料字段及协议保存时编码/默认值保留。它不是原生桌面端端到端测试。

## 明确边界

- 动态嵌套数组、子记录内部条件、子记录内运行时变量还没有完整的递归执行器。编辑保存会保留原始子结构，但当前条目编辑器明确阻止这些结构的错误发送，不宣称已经全面适配。
- 分支当前仍使用前置字段等值条件，不是任意表达式或完整流程状态机。
- 同一通道同一协议的“停止周期发送”会停止该协议下各终端的周期任务；启动任务的参数与身份彼此隔离。
- 此次修改为源码；正在运行的旧桌面程序不会自动获得后端更新。请在停止现场收发后重新编译启动。不要同时用旧、新程序写同一数据库。
- Windows 拒绝了当前会话对原生窗口的自动化访问，因此采用浏览器交互测试加真实 UDP 引擎测试，没有声称完成原生窗口操作验收。
