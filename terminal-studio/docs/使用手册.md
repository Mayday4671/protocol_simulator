# 多协议 UDP 终端模拟系统 — 使用手册

版本 v0.1.0 ｜ Windows 64 位

一款面向协议联调与信令仿真的 UDP 终端模拟器：把通信协议录入系统后，即可在图形界面里配置参数、收发报文、自动应答、管理设备档案，全程十六进制字节级可控。

---

## 1. 安装与启动

### 安装版（推荐）

双击 `Simulated Terminal_0.1.0_x64-setup.exe`，按向导完成安装，从开始菜单或桌面快捷方式启动。

### 绿色版（免安装）

拷贝整个 `dist_portable` 文件夹到任意目录，双击其中的 `simulated-terminal.exe`。
**注意：`WebView2Loader.dll` 必须与 exe 在同一目录，请随文件夹整体拷贝。**

### 首次使用

1. 系统自带一套「视频通信协议」示例（管理面 + 设备面，含多轮交互流程）。
2. 若使用自己的协议，见 [第 8 节 协议模板导入导出](#8-协议模板导入导出xml)。
3. 数据库自动创建于 `%APPDATA%\com.simterm.desktop\simterm.db`，卸载或重装不影响该文件。

### 界面主题

侧边栏左下角两个按钮：

- **调色板（皮肤设置）**：12 种主题色即时切换；可选本地图片做全局背景，「皮肤浓度」滑杆同时控制背景浓度与界面通透度；设置自动持久化。
- **太阳/月亮**：明亮 / 暗黑模式切换。

## 2. 基本概念

| 概念 | 说明 |
|------|------|
| 通道（节点） | 一个 UDP 端点：本地监听地址端口 + 对端目标地址端口 + 设备编号。模拟器以通道为单位收发报文 |
| 系统 | 一套协议的顶层容器（公共头与字典都挂在**分组**上，系统仅作容器） |
| 分组 | 系统内按业务对协议的二级归类（如 注册 / 会话管理 / 视频通信） |
| 协议 | 一条报文的定义：字段表或模板 + 匹配正则 + 自动应答链 |
| 公共头 | **分组级**报文头，拼在该分组每条协议报文最前面（同系统不同分组可各配不同的头）；协议字段用「覆盖公共头」标记显式指定头字段取值 |
| 字典（字典） | 十六进制值 ↔ 中文含义对照表，绑到字段后下拉选择、解析显示中文 |
| 字段语义 | 字段上的显式标记（会话/设备序列号/设备列表/操作类型/配置结果/源设备/目标设备），引擎按标记提供自动化能力 |

**三层结构：系统 → 分组 → 协议。左侧树点击系统名即选中并折叠/展开其分组。**

## 3. 通道管理

进入「通道管理」→ 新建通道：

- **名称**：便于识别，如「温湿度传感器」
- **本地监听**：本机绑定地址与端口（如 0.0.0.0:9001）
- **目标地址**：对端 IP 与端口（如 127.0.0.1:4001）
- **终端编号**：设备 ID 十六进制，供报文中 `{node_id}` 变量引用，**字节数须与协议字段一致**
- **角色**：模拟设备 / 监测平台（仅标注用途，无功能限制）

点击「启动」开始监听；启动后收到的报文实时进入监控。

## 3.5 协议录入要点

- 字段行**拖拽手柄**（左侧 ⠿）调整顺序，也可用上移/下移按钮微调
- 弹窗再长**保存按钮始终可见**（底部固定条）
- **字段名允许重复**：同名字段各自独立（长度/取值互不影响），界面显示为 `字段名(2)`
- **「覆盖公共头」列**：字段需要改写分组公共头某字段取值时选择对应头字段（显式声明, 不再按名字隐式绑定）；该字段不重复拼入消息体
- **匹配只按「字段匹配条件」**：选字段+期望值, 全部满足才命中（值可写 hex / 十进制 / 字典含义）; 应答协议建议放在请求协议前面并带「响应结果=成功」条件, 避免应答帧误中请求协议
- 公共头与分组专属字典在**协议管理左侧树选中分组**时配置（严格隔离: 分组之间互不影响, 不回落系统）

## 4. 交互控制台（核心操作页）

四级筛选：**通道 → 系统 → 分组 → 协议**。选择后页面生成参数表单。

### 4.1 字段填写

- 普通字段：直接填写十六进制（如 `FF A1`）
- **字典字段**：下拉选择条目（显示「值 · 含义」）
- **自动字段**（留空即自动，填值即覆盖）：
  - 源设备ID → 跟随通道节点编号
  - Session → 节点当前会话（未认证填 00）
  - 序号 / 报文总长 / 时间戳 / 随机数 → 发送时自动计算
- **源/目标设备**字段：下拉直接选节点或已配置设备，选中自动填 hex
- **公共头（分组级）**：默认折叠，点击展开可查看并修改头字段（改值即覆盖，清空恢复定义值）；公共头配置入口在「协议管理」左侧树选中某**分组**时出现

### 4.2 发送与批量

- **发送报文**：按当前表单发送一条
- **设备条目 / 批量配置**：协议含变长设备列表时，「条目数」输入台数（十六进制），下方自动生成逐台填写表单——每列的控件类型由协议子字段定义决定（字典=下拉、序列号=可输可选、其余=hex 输入）；新行默认值自动递增，点发送即一条报文携带全部条目
- **周期发送**：心跳类协议可开启周期发送（毫秒间隔），下方「周期发送任务」列表可单独停止
- 发送后**无需切页**：下方内嵌「实时监控」终端即时显示收发流，双击任意行可查看解析详情

### 4.3 设备条目说明

条目数按协议定义的字节宽度填写（如 1 字节填 `05` 表示 5 台）。数量变化时已填内容保留，只增删尾部行；校验出错会精确提示「第 N 台的某字段需 X 字节 hex」。

## 5. 自动化能力（按字段语义触发）

| 能力 | 触发条件（协议配置） | 行为 |
|------|---------------------|------|
| 会话认证 | 字段语义=会话 | 收到该字段的值自动存入节点；之后该节点所有报文经 `{session}` 自动携带 |
| 设备档案入库 | 应答中语义=配置结果的字段取值=字典第一条（成功） | 回溯触发请求，把设备列表中序列号写入设备档案字典 |
| 档案移除 | 请求中语义=操作类型的字段值对应字典含义含「删除」 | 应答成功后把列表序列号从档案移除 |
| 应答回填 | 应答字段值写 `{req:字段名}` | 自动应答时取请求报文中该字段的实际值 |
| 自动应答链 | 协议配置了 AutoRespond | 收到匹配报文后按延迟自动回应答；链路多步可级联到底 |

> 会话认证、档案入库均为通用机制：换一套协议，只要字段标注了对应语义，能力自动生效。

## 6. 实时监控

- 独立页与控制台内嵌终端共享同一日志流
- 工具栏：关键字搜索、方向过滤（收/发）、通道过滤、十六进制/文本切换、自动滚动、暂停/清屏
- **双击任意报文行**：打开字节级解析视图——按字段分组的大方格，每格含 0x 十六进制值、起始序号、中文含义、长度与十进制；变长设备列表按台拆开逐字段显示中文；支持导出解析文本、复制原始报文

---

## 7. 设备管理与字典管理

**设备管理**：集中查看所有已入库设备（序列号 hex、名称、归属），支持手动添加/移除；档案数据来源 = 各协议「设备序列号」语义字段绑定的字典（自动聚合，全局可用）。

**字典管理**：左侧字典树（按 系统/分组 分组，可折叠），右侧条目表格（值/含义/排序）增删改。字典两档：**全局共享**（如设备档案，跨分组可见）或**分组专属**（同 Key 时分组覆盖全局，不同分组的同 Key 字典互不影响）；被协议引用的字典删除时会被拒绝并提示引用方。

## 8. 协议模板导入导出（XML）

入口：协议管理页右上角。

### 导入

「导入 .xml」选择模板文件，按协议 ID 幂等导入（重复导入=更新）。模板结构：

```xml
<simterm-import>
  <!-- 根级 dict = 全局共享字典（如设备档案, 跨分组可见） -->
  <dict key="device_sn" name="设备档案" byte-len="4">
    <item value="00000001" label="设备序号0001"/>
  </dict>
  <system name="我的协议" description="说明">
    <group name="注册">
      <header enabled="true">                     <!-- 分组公共头（同系统各分组可不同） -->
        <field name="帧头" len="2" enc="hex" value="55 AA"/>
        <field name="Session" len="2" enc="hex" value="{session}" role="session"/>
      </header>
      <dict key="msg_type" name="消息类型" byte-len="1">   <!-- 分组专属字典 -->
        <item value="01" label="注册请求"/>
      </dict>
      <protocol id="reg_req" name="注册请求" type="Request"
                match="^55AA0101" auto-respond="reg_resp" delay="100">
        <!-- 字段条件匹配: 与正则并用, 全部满足才命中 -->
        <match>
          <cond field="消息类型" value="注册请求"/>
        </match>
        <!-- header-ref: 显式覆盖公共头某字段的取值（同名但不标记的字段独立存在） -->
        <field name="类型" len="1" enc="hex" value="01" dict="msg_type" header-ref="消息类型"/>
        <!-- 变长列表: 值 {vlen}, 子元素声明每条记录布局 -->
        <field name="设备列表" len="12" enc="hex" value="{vlen}" role="device_list">
          <unit name="设备序号" len="4" enc="hex" dict="device_sn" role="device_sn"/>
          <unit name="设备类型" len="2" enc="hex" dict="device_type"/>
        </field>
      </protocol>
    </group>
  </system>
</simterm-import>
```

**字段属性**：`name / len / enc(hex) / value / dict / role / header-ref`
**协议内字段名允许重复**（同名第 2 个起内部自动区分, 界面显示为 `字段名(2)`）
**语义 role 取值**：`session` 会话、`device_sn` 设备序列号、`device_list` 设备列表、`device_count` 设备数量、`op_type` 操作类型、`result` 配置结果、`src_id` 源设备、`dst_id` 目标设备
**值内可用变量**：`{node_id}` 节点编号、`{session}` 会话、`{seq}` 自增序号、`{tlen}` 整帧总长、`{timestamp}` 时间戳、`{random}` 随机数、`{vlen}` 变长占位、`{req:字段名}` 应答回填、`{dict:key}` 字典默认条目

### 导出

「导出全部」或按树选中后导出，生成含公共头/字典/协议的完整 XML，可在其他机器导入还原。

### 命令行批量导入（可选）

有 Python 环境时：`python scripts/import_xml.py <模板.xml>`

## 9. 测试服务端（联调用）

`scripts/udcp_server_gui.py` 为图形化 UDP 测试服务端（需 Python 3.10+）：

```
python scripts/udcp_server_gui.py 4001 --auto
```

- `--auto` 启动即监听；日志分色显示收/发/信息/错误
- 按当前「视频通信协议」实现全部应答：注册分配 token、心跳确认、注销吊销、6 步呼叫链自动接力、管理面配置/参数下发/记录查询全流程
- 按钮可主动下发配置请求与需确认数据

## 10. 常见问题

**Q：发送报「字段 hex 值需 N 字节」？**
字段值实际字节数与声明不符。检查是否多敲/漏敲了十六进制位；数量类字段注意是十六进制（`05`=5）。

**Q：下拉显示「字典无条目」？**
该字段绑定的字典在当前系统作用域内没有条目。到「字典管理」选中该字典添加条目，或检查协议归属系统是否正确。

**Q：收不到自动应答？**
确认对端报文能被**匹配正则**命中（协议管理的匹配正则列），且应答协议 ID 存在。管理面协议注意正则与实际字节偏移一致。

**Q：绿色版启动报 WebView2Loader.dll 缺失？**
`WebView2Loader.dll` 必须与 exe 同目录；请整体拷贝 dist_portable 文件夹。

**Q：换了新 exe 后任务栏图标还是旧的？**
Windows 图标缓存所致，不影响使用；复制 exe 改名或重启资源管理器即可刷新。

**Q：数据在哪里？如何备份？**
`%APPDATA%\com.simterm.desktop\simterm.db`，拷贝该文件即完成备份；配合协议 XML 导出可完整迁移。
