## 最终目标

开发无需登录、无需独立服务器/数据库服务的 Windows 10/11 x64 桌面应用，最终生成真实可安装的 NSIS `Setup.exe`，而不是仅做 HTML 页面、静态后台或伪功能展示。应用必须能创建/导入 XML 协议、编辑/复制字段和字段组、使用协议生成真实 UDP 报文、真实监听和解析 UDP、定义和执行交互流程、管理设备、视频/语音呼叫及 RX/TX 带宽资源、监控日志并导出数据。

## 技术栈不可随意改

- Tauri 2 + Rust (stable, edition 2024) + Tokio 1.x + SQLite (rusqlite) + quick-xml；核心协议编解码、UDP 和流程执行都必须在 Rust 层。
- React 19 + TypeScript 5.x + Vite + Ant Design 5.x + Zustand + TanStack Query + @xyflow/react 12.x + Monaco Editor + TanStack Virtual。
- 依赖实际小版本选择互相兼容的稳定发布版后锁定 pnpm-lock.yaml/Cargo.lock/rust-toolchain.toml。pnpm 为唯一 JS 包管理器。
- XML 为协议可编辑源文件；内部编译为强类型 AST；图形字段表/在线 XML Monaco 双向编辑；允许复制字段、字段组、信令与模板，复用公共片段并检查 key 冲突。
- 只在本地存储 SQLite 和协议 XML；默认离线可用。Windows NSIS 安装包要支持 WebView2 离线 installer。

## 绝对不能做错的业务规则

1. MUSP 示例公共头 23B，信令码 1B、会话ID 2B、源/目标地址各3B；不能照原型图片把信令码写成两字节。
2. 设备外显状态**只能三态**：OFFLINE `00`、ONLINE `01`、COMMUNICATING `02`；流程等待、注册中、资源回收中不是设备状态。
3. `0x22 CONFIG_RESULT` 的专用业务体严格 `itemCount(1B) + result[itemCount](每项1B)`；`AA` 成功，例 `05 AA AA AA AA AA`；不得凭空添加总结果、失败条目索引或为未知结果造中文失败码。
4. `0x21` 允许单个配置条目映射一台设备，或多个条目映射一台设备的多组参数，动态 itemCount×itemSize；前面**按信令模板可选**8B配置通用段（Bit7原子性、Bit0结束标识目前只是候选业务定义）。
5. 编码和解码共享一份 Schema：协议定义表只有序号、字段名称、字节长度、HEX类型、说明；实际报文解析应显示字段位置、HEX/DEC/BIN/中文解释、枚举、Bit和数组并双向定位。
6. 每个需要等待响应的发送节点必须在 `UdpSocket.send_to` 前登记 PendingRequest；按响应信令码初筛，再以设备、endpoint、事务序号、会话规则作唯一匹配；按节点处理超时、重试、重复、迟到、并发冲突。
7. VIDEO_CALL_REQ 和 VOICE_CALL_REQ 提交**申请带宽**；`0x70 RX`/`0x71 TX` 分别下发**实际资源**，各自等待 `0x72`；视频 A/B 合计通常四项，单端语音 A 两项。启动方式 LOCAL_READY/CONTROL_NOTIFY 配置选择。
8. A/B/控制主动结束以及离线/心跳掉线都要触发通话结束和各设备 RX/TX 资源撤销；ACK 丢失时资源为 UNKNOWN，不可虚假回池；结束某一通话不影响其他通话。
9. 手动与报文创建设备均可用，新设备默认 OFFLINE，配置更新已有设备不能自动清空其注册与通信状态。
10. 所有内置示例应根据原始 MUSP v0.8 文档构造；v0.8 尚未确认的业务字段如通用8B剩余字节必须标记为候选，不可写死为行业规定。

## 工程执行方式

按 S0→S6 分阶段持续实现（参考 `08_迭代计划与Windows安装包.md`），**不要先把七张图拼成一套静态组件才去实现通信层**。优先 S0 Tauri 基础 → S1 Rust XML Schema 编译+Codec+golden vectors → S2 多 UDP 端点与报文监控 → S3 设备/会话 → S4 React Flow 及 PendingRequest → S5 通话资源 → S6 测试、打包。

在每一阶段：

- 直接创建/修改文件，运行与当前环境兼容的实际测试；给出命令、运行结果、已完成/未完成项，禁止宣称未运行的测试通过。
- 代码应可维护、清晰分层，所有 IPC 有类型；新增公共字段/节点需补对应单元测试。
- 遇到真实业务有歧义先根据文档优先级选可配置实现并记入 `docs/OPEN_QUESTIONS.md`；不要任意编造协议值或重写用户的业务原文。
- 不能因为本机不是 Windows 就跳过开发；实现跨平台可编译的 Rust 核心/前端并说明 Windows NSIS 验收需 Windows runner，但**不得声称已构建 EXE**。
- 每阶段输出进展，但持续工作，不要在只做了脚手架后宣布整个项目完成。

## 初始验收任务（必须优先做到）

A. 创建项目并可运行 Tauri + React 主窗体，有暗/亮主题一键切换，7 页路由均可进入。
B. XML 编辑器（Monaco）中粘贴 `06_示例与测试数据/musp-demo.xml`，可解析、可视化、复制字段、验证并发布；CRC/动态数组/Bit单测可运行。
C. 运行 `06_示例与测试数据/generate_golden_vectors.py`，Rust Codec 可解码其 99B CONFIG_SET 与 31B CONFIG_RESULT，并编码回相同字节；显示 Bit81 / 5条10B / 逐条AA。
D. 通过127.0.0.1两个UDP端点真实发送/接收并将日志落库，接收结果可以在可视化HEX/中文解析页看到。
E. 设备手工建立和按5条配置响应更新都能真实运作，状态严格三态。
F. 最终需要能在 Windows 上构建 NSIS 安装 EXE，提供文件位置、SHA256 与安装测试记录。
