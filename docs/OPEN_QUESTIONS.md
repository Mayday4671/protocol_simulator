# 待确认业务规则

1. configCommon8 的 Bit7/Bit0 为候选业务解释，剩余七字节用途未确认。保留可编辑 XML 定义；不开启隐含回滚或批次提交语义。
2. CONFIG_RESULT 仅 AA 为已确认成功；其他值保留 HEX 并标未知/未确认成功。
3. 配置生效策略（全部成功/逐项成功）、映射模式（多设备/单设备参数）、LOCAL_READY/CONTROL_NOTIFY 由场景显式选择。
4. 原始讨论稿标题仍含 v0.7，但变更章节/交付基线为 v0.8；原文保留不改。
5. 提供 XML 样本仅含 0x21/0x22；其他信令须从原始业务表补充，不能由原型推导。
6. 通用 XML 的信令码可与 MUSP 重合。设备注册、配置、通话等内置业务及虚拟对端仅对 XML `protocol.id="musp-v08"` 或 `"musp-demo"` 明确启用；其他 ID 只执行通用编解码、真实 UDP 和流程等待。用户将 MUSP 协议改名为其他 ID 后默认不启用内置业务，未来如需独立的业务适配器配置应另行设计，不通过信令码猜测协议身份。
