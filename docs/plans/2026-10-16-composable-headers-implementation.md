# 公共头组合实施与验收顺序

设计依据：[公共头组合与信令工作区设计](2026-10-16-composable-headers-design.md)。本表是实施检查点，不是已完成记录。

目标：在现有 Windows Tauri 客户端中完成公共头独立管理、逐信令组合、显式参数复用与真实 UDP 收发。

技术栈：现有 React/TypeScript、Rust、XML、SQLite、Tauri/NSIS。原无人机协议保持兼容。

## S5：真实收发与解析

修改 `musp-engine/src/runtime/flow.rs`、`pending.rs`、`flow_host.rs` 及通用收包分发；保留 `SignalByteLayout.tsx`，适配头实例元信息。

- [x] 同一流程连续发送 A、B、A+B，并按不同组合接收响应。
- [x] 接收后响应显式复制当前请求字段；并发两次请求不串会话和事务值。
- [x] 歧义报文留在收发记录中，不自动应答，不被等待节点消耗。
- [x] 客户端观察分头彩色字节块、中文含义、数组与 Bit；控制台无需跳页查看发送结果。
- [x] 以正常速率执行协议和客户端回归，不扩大为高吞吐压测。
