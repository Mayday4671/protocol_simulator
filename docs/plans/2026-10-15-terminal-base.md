## 边界与后续接线

原基座使用 Tailwind/Radix 与 sqlx，按用户最新“以它为基座”的决定保留，避免为恢复原栈而重做用户选择的界面。新协议内核保留 Rust 2024、quick-xml；旧兼容模块暂保持原模型。

MUSP XML 不能转译为旧版仅支持 Hex/Uint/Ascii 的字段表，否则会丢失 CRC、动态表达式、Bit、secret 和 PendingRequest 语义。schema-core 的迁移不代表旧版导入器/流程已经支持 MUSP。新范围要求现在开始明确 Schema 路由接线，复用 0.1.2 已验证的事务、设备、会话和通话业务实现；不能复用旧版“首个字典条目=成功”与“同码响应=注册成功”的规则。此前的 0.1.2 验收只作为行为基线，不能充当新副本的通过证据。

## 实际导出项目能复用什么

只读检查 `musp-studio/release/无人机UDP联调示例.zip`：manifest 的 formatVersion=1、productVersion=0.1.2；所有 3 个载荷 checksum 与文件一致。项目有 2 个端点、1 个系统、5 台设备、8 个流程及 12 个流程版本快照。两份 XML 对应草稿/发布对象，内容相同，均为 34 信令的 `<protocol id="musp-v08" version="0.8.0">`，SHA256 为 `0b3b44504488e8481d91a307879958b941e822847eaf30381e8f1cf8f4a4f896`，与 `musp-studio/protocols/musp-v08.xml` 一致。

八个流程分别是多设备配置、免认证注册、三轮心跳、视频、语音、认证注册、认证业务命令、单设备参数配置。它们使用结构化 `values`、`response.header/body` 路径、ASSIGN、CONDITION、WAIT_EVENT、UPDATE_SESSION/CALL/RESOURCE；不是旧 `FlowStep` 的参数字符串列表。ZIP 中设备均 OFFLINE，三个会话 active=false；没有可直接恢复为已认证运行状态的 Token。保存的通话/资源历史不是允许重新发送或重新激活的命令。

复用协议 XML、流程版本与静态参数时，必须显式导入到新工作区、重新映射实体 ID 并保持发布快照；不能直接覆盖旧用户项目、复制在线状态或沿用 session。旧 ZIP 项目导入格式与 `<simterm-import>` 也不同。

## 响应取值必须明确来源

只读核查结论必须区分语法和默认行为：旧 API 的 `params={}`、控制台 `values={}` 是“没有手动覆盖值”，**不是已取得响应**；旧 `{last:字段}` 没有捕获值会报错（`core/src/template.rs:206–219`），并非所有缺值都会补 `{}`。但以下真实行为不能进入 MUSP 路径：

- `Node.capture_buckets()` 对无效 JSON 使用空 map（`core/src/models.rs:122–126`），掩盖损坏与未获得值的差别。
- 原基座 `{session}` 缺失时补零、截断超长值；已修复为缺失/宽度错误时拒发。所选设备不再仅凭字段 role 强制覆盖固定值。零仅可由初始注册等明确规则允许，不能成为运行期缺值的默认修复。
- 原基座自动应答会隐式回填同名空字段；已移除，只允许显式当前收包引用，并按源/目标编码保持字节一致。普通捕获字段收到零值会覆盖旧值。当前收包与最近捕获仍不等价于某次合法响应的完整事务快照。
- 失败/超时无分支却汇总 done 已修复，非法/空步骤 JSON 也拒绝运行。旧等待仍仅查询日志的 node/protocol/id，捕获仍不是 MUSP 的事务关联，不可当作其 Token 来源或业务成功判定。

新基座已有明确来源编辑器，覆盖协议字段、公共头、流程字段和控制台动态字段。固定值、当前收包字段（仅自动应答）、最近捕获字段、已捕获会话与内置值分别选择；高级表达式保留兼容。空引用、手动发送当前请求引用、清空覆盖后偷偷回退旧值会报错。不再预置新协议的 FF A1/01 或自动选择新流程的首条信令。

新接口的 `response` 初始应为不存在；只有校验通过且唯一关联的报文才能赋值，必须带 packetId、runId、stepId、协议版本及完整 values。缺路径、错类型、缺会话、Token 过期应在下一次发送前给出具体错误，禁止 `unwrap_or_default()/json!({})` 后继续发送。显式 `0`、合法空参数 bytes 与“缺失”必须分别处理；显示值与保存/发布默认值不能反向覆盖真实响应或运行变量。

## 最小真实接线顺序与接口

下面是建议接口合同，**不是已经实现的命令**。数据库内部 ID 可先保留既有类型，通过适配层映射，避免重写旧 UI。

1. **协议版本与 codec 路由。** `ProtocolBinding { codecKind: Legacy | Schema, protocolVersionId, businessProfile }`；MUSP 业务仅在显式绑定时启用，不按 0x21 等码值猜测。Schema 保存原 XML 与不可变编译快照。已存在的 `compile_xml(source)`、`CompiledProtocol.encode(code, &serde_json::Value)`、`decode(bytes)` 可直接使用。encode 已输出完整帧，禁止再拼旧公共头。
2. **控制台真实发送和解析。** 新 `SchemaSendRequest { nodeId, protocolVersionId, messageCode, values: Value, deviceId?, sessionId?, runId?, stepId? }`；旧 `HashMap<String,String>` 仅用于 Legacy。UI 继续字段表单，数组用行编辑、枚举下拉、响应引用选择具体路径，JSON 作为高级入口。返回 `DecodedPacket.fields/values/diagnostics`，保持字节范围、HEX/DEC/BIN/中文；raw、tree 和 values 三条展示/导出通路均需按 secret 脱敏。
3. **事务主机接线。** 复用 0.1.2 `runtime/pending`、变量解析及 FlowEngine；`prepare_send` 先解析真实值并编码，从实际字节建立 PacketMeta，再 `register`，最后 send_to。接收先按绑定版本 decode 与验证，再唯一 pending/显式异步事件分派；业务验证通过才更新 domain，输出真实响应快照。发送失败撤销等待；超时、取消、迟到和重复均有终态。
4. **首个业务闭环。** 同一控制台完成 `21→22` 两种映射、`01→02→03→04` 免认证注册及 `31→32` 三轮心跳，随后加入 `11→12` 认证与 `51→52`。配置模式 01 允许在空设备库下由控制端发起，不能复用旧 start_flow 的“必须先选已有设备”门槛；成功关联的逐 AA 结果才创建/更新设备。注册、认证命令和通话则按各自规则要求实际设备及有效会话。
5. **状态和通话闭环。** 复用 `41` 数组/有符号解析，再接视频寻呼、语音、RX/TX、结束/取消/离线；放在控制台场景和设备上下文，不新增独立带宽资源页。后端仍需原子准入：容量不足在 61/66 许可前以基线 04 拒绝；半成功时补偿，UNKNOWN 不回池。不能把“无资源页面”解释为取消这些协议规则。

建议 `ResponseContext { packetId, protocolVersionId, runId, stepId, correlation, values }` 与 `SessionKey { system, protocolVersion, endpoint, remote, logicalDevice, wireSession, epoch }` 独立于旧捕获桶。应复用现有受测业务方法而非用字段名推断 session 或 call；异步 11 不能消费正在等 02 的 pending。

每段接线先做少量真实 UDP 回归，再从客户端执行同一动作。首段至少覆盖：CRC/长度错误不能更改设备；5 条配置遇非 AA/数量错不误提交；两设备乱序响应不串配；注册拒绝/session=0 不继续 03；认证缺 Token/过期阻止发送；21 同码的非 MUSP 协议不触发设备业务；字段缺失不得变成 `{}`、0 或字典首项。通话段补容量不足、部分配置失败、两通话独立结束及迟到 ACK，不做压力测试。
