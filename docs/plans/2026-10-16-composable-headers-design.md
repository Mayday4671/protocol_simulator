# 公共头组合与信令工作区设计

日期：2026-10-16。状态：设计完成，尚未实现。依据：用户要求独立公共头 A、B，并允许同一流程使用 A、B、A+B 三种信令；基于 terminal-studio 继续开发。本文不修改 MUSP v0.8 或无人机协议业务规则。

## 1. 使用模型

公共头定义只描述结构。信令引用公共头定义并决定拼接顺序。参数配置保存一次测试使用的字段值或明确的数据来源。流程节点选择信令及参数配置。

| 对象 | 负责什么 | 不负责什么 |
|---|---|---|
| 公共头定义 | 字段、类型、顺序、长度、枚举、Bit、计算规则 | 某台设备的地址或某次会话 |
| 信令定义 | 有序公共头引用、业务体、尾部、收包识别条件、应答关联 | 当前测试的实际字段值 |
| 公共头参数配置 | 某个公共头的一组固定值、设备字段或流程输入绑定 | 改动字节结构 |
| 流程节点 | 选择信令、参数配置、本节点覆盖和当前响应取值 | 复制并维护一套公共头定义 |

例：信令一=A→业务体；信令二=B→业务体；信令三=A→B→业务体。组合属于各条信令，同一流程不绑定唯一公共头。A→B 与 B→A 是不同报文布局。

公共头可以没有、一个或多个；同一定义重复使用时需要不同实例别名。无业务体、只有公共头的信令也合法。这里的“公共”指结构复用，不要求所有信令包含它。

## 2. 协议管理：结构与组合

保留现有“协议管理”入口，不增加顶层导航。页内左侧分为公共头、信令、复用结构、尾部四组；中间是结构化编辑器；右侧是选中字段属性。XML 源码作为同一文档的可切换视图，不要求用户为了组合公共头手写 XML。

### 2.1 公共头编辑

选择“公共头 A”后显示字段表和字节布局。支持新增、复制字段、枚举、Bit、结构引用、数组。引用处统一使用这个定义；修改草稿时显示受影响的信令数量，已发布版本不被就地修改。

公共头有稳定 ID 和用户名称，字段有稳定 key 和中文名称。名称变化不破坏引用。删除被引用的公共头会阻止操作并列出使用位置，允许用户先替换引用。

### 2.2 信令编辑

```text
协议管理      [协议版本]                              [保存草稿] [校验并发布]
┌─────────────────┬─────────────────────────────────────────────────────┐
│ 公共头          │ 信令：设备状态上报                                  │
│   A 基础头      │ 报文组成                                            │
│   B 扩展头      │ [A 基础头 ×] → [B 扩展头 ×] → [业务体] → [尾部]     │
│   ＋ 新建       │ [添加公共头]     [上移] [下移]                        │
│ 信令            │                                                     │
│   信令一        │ 选中：B 扩展头     引用定义 [打开公共头定义]           │
│   信令二        │ 实例名称：扩展头    实例标识：extension              │
│   信令三        │                                                     │
│ 复用结构 / 尾部 │ 业务字段编辑                                        │
│                 │ 收包识别 [展开]   完整报文字节布局 [展开]             │
└─────────────────┴─────────────────────────────────────────────────────┘
```

移除引用只改变这条信令，不删除公共头定义。不允许在引用位置悄悄修改共享结构；“复制为独立公共头”必须显式操作并生成新 ID。

公共头组合不等于任意勾选。默认按信令定义完整组装；需要条件扩展时由协议定义启用条件，发送界面不能随意关闭必需的头。

### 2.3 版本

发布协议时冻结所有引用定义、顺序和识别规则，组成一个可复现的协议快照。运行中的流程继续使用原快照。草稿变更不能改变运行实例。

## 3. 交互控制台：填一次、按需覆盖

顶部保持协议、本地通道、远端地址。左侧信令构造，右侧收发和可视化解析始终可见。

```text
[协议版本] [本地通道] [启动/停止监听] [远端地址]
┌──────────────────────────────────────┬───────────────────────────────┐
│ 信令 [信令三]                        │ 收发报文                       │
│ [A 基础头] → [B 扩展头] → [业务体]   │ TX / RX · 信令名 · 对端 · 状态 │
│                                      │                               │
│ A 基础头    [参数配置：控制端 A ▾]    │ 信令解析                       │
│ 源地址   00 00 01  来自配置           │ 公共头 A / 公共头 B / 业务体   │
│ 目标地址 00 00 3B  本次覆盖 [恢复继承]│ 彩色字节块、HEX、DEC、含义      │
│ [编辑本次值] [保存为参数配置]         │                               │
│ B 扩展头    [参数配置：测试会话 ▾]    │                               │
│ 会话号   [填写或选择明确来源]          │                               │
│ 业务体                               │                               │
│ ...                                  │                               │
├──────────────────────────────────────┤                               │
│ HEX 预览 / 缺失字段                  │                               │
│                [编码预览] [发送一次] │                               │
└──────────────────────────────────────┴───────────────────────────────┘
```

地址仅为界面排版示例，不能作为创建项目后的默认值。

### 3.1 参数保留

- 切换信令保留每条信令的本次草稿；用户选择过的公共头参数配置可以在同版本、同公共头引用间复用。
- 公共头参数配置显式保存，归属项目和协议版本，支持复制、重命名；不自动跨项目套用地址或会话。
- 从 A 切到 A+B 时保留 A 的已选配置；B 没有选过配置则明确显示“未选择”，不猜值。
- 本次覆盖属于信令及公共头实例，不回写配置，不影响另一条信令。配置变化使引用它的未覆盖字段更新，并让旧编码预览失效。
- 重置拆成“清除本次覆盖”和“恢复信令草稿”，避免一个按钮清空所有公共头值。
- 字段或配置不兼容时列出失效字段；不按中文名称或相同 key 跨结构强行迁移。
- 普通未保存编辑保持页签关闭保护；只有明确保存的参数配置保证重启后恢复。密钥不进入普通明文参数配置和导出文件。

### 3.2 值来源与优先级

固定常量、信令标识、长度和校验字段由协议决定，不参与普通覆盖。

对可编辑字段，优先级为：本次/节点显式覆盖 → 当前选中的公共头参数配置 → 协议声明的默认值。更高层配置了动态来源但来源缺失时立即报错，不回退到低层值。

固定值 0、false、有效的空数组不能被当作“未填写”。清空覆盖与输入空值是不同操作，提供“恢复继承”按钮。

流程值来源提供：固定值、流程输入、流程变量、设备字段、当前匹配报文、显式保存的历史响应变量。用户选择来源和字段，显示中文来源说明；内部可以保存表达式，但不向用户自动填入 `{}` 或未经选择的路径。

手动发送不能引用不存在的“当前响应”；如需从历史报文取值，用户必须选择具体报文/字段，显示时间及方向，明确是复制当时的值。事务号、会话号不会因同名而自动共享。事务号自动生成只能在协议或流程明确配置生成器后启用。

### 3.3 错误与按钮

未选通道、未启动监听、缺失字段分开提示。缺失字段如“公共头 A / 源设备地址未填写”直接定位对应输入框，同时展示来源失效原因。显示内部 header.srcAddr 作为可展开技术详情，不把它当唯一提示。

编码预览只依赖协议和参数，不要求监听已开。发送必须有有效预览、运行中的通道和远端地址；禁用原因始终可见。修改字段、组合版本或配置后，旧预览立即作废。

## 4. 流程：复用参数，但响应上下文严格隔离

流程编辑中增加“公共头参数”配置区，列出本流程实际使用的公共头，不要求所有节点共用一个头。每个公共头可选择参数配置或绑定运行输入。

节点选择信令后，显示只读组合条 A/B/A+B；节点参数分为公共头覆盖和业务字段。默认继承流程选择的配置，不拷贝结构。修改节点信令时保留兼容的显式绑定，不兼容的显示待修复并禁止发布。

被动等待、接收后响应、主动发送等待都使用同一组合编解码。等待节点按稳定信令 ID 和显式关联字段匹配；不能假设每种 UDP 协议都有会话号、事务号、设备地址或 1B 信令码。

并发请求的“当前匹配报文”属于各自运行实例及等待节点，不能借用另一个实例或上一条无关报文的值。请求和响应可以采用不同公共头组合，字段复制通过显式绑定完成。

## 5. 数据与 XML

继续以 XML 作为协议定义源，Rust 编译后的 AST 为派生结果。界面结构化编辑和源码编辑共享同一草稿，往返不丢未知受支持属性。

新版结构使用稳定的公共头实例别名隔离字段，如 `headers.base.srcAddr` 和 `headers.extension.srcAddr`。同名字段不覆盖，重复使用同一公共头时需要不同实例别名。旧协议继续保留 header.* 路径，不强制迁移现有流程。

概念 XML（待实现的 schemaVersion=2 契约，不声称当前编译器已支持）：

```xml
<message id="signal_three" nameZh="信令三">
  <headers>
    <use ref="header_a" as="base" />
    <use ref="header_b" as="extension" />
  </headers>
  <body><!-- 该信令业务字段 --></body>
  <trailer><!-- 协议要求的尾部 --></trailer>
</message>
```

信令 ID 是定义和流程的主键，线路上的信令码是普通受约束字段，可按实际协议为不同宽度；不能再用全局 u8 值替代所有协议的信令身份。对旧版 MUSP 保留 code/responseCodes 兼容适配。

每次发送记录完整布局快照 ID、最终值和各字段来源，不记录密钥明文。公共头参数配置保存 definitionId、协议版本、字段来源及值，不保存另一份字段结构。

长度、CRC 等计算引用明确范围：某个头、全部头、业务体、指定起止字段或整帧；根据实际协议选择。现有 MUSP 的计算范围和字节结果保持原样，不给新协议自动套用 CRC16 或固定尾长。

## 6. 被动收包识别

当前引擎强制所有信令信令码处于相同偏移。新版按信令编译识别条件：固定同步字、类型/信令字段、长度约束；条件可在不同偏移，均受协议定义控制。结构上的固定字段可以成为识别条件，界面能查看它们，不能隐式把任意业务值当识别依据。

接收流程：通道确定协议版本 → 有界匹配候选信令 → 按各自完整布局解码并验证 → 唯一成功才生成可用于流程匹配的解析报文。

- 0 个成功：保留原始报文，显示不匹配或截断/校验失败原因。
- 多个成功：显示“识别冲突”和候选信令，不采用第一个，不自动触发响应。
- 人工可指定某个候选查看解析，但不因此把报文作为自动流程事件重放。
- 编译期发现完全相同的识别规则时禁止发布；不能静态证明互斥的规则进行运行时唯一性校验。
- 识别前限包长、候选数、数组数量和解码步数，避免构造报文造成无界工作。
- 对没有协议内区分标识的场景，允许用户为监听通道显式限制接收信令；不依赖“当前界面选中了哪条信令”来猜包。

## 8. 验收标准

1. 用户在客户端创建 A、B，组合三条信令；无需手写 XML。
2. 三条信令按 A、B、A+B 顺序编码，对端实际收到的字节与定义逐字段一致。
3. 同一流程依次发送三条信令；被动接收和响应也能采用不同组合。
4. 不同信令码偏移能识别；未知、截断、校验失败和歧义报文不触发错误响应。
5. A/B 都有同名字段、同一公共头引用两次时，值与解析路径互不覆盖。
6. A 的配置选择后切换到 A+B 可复用；B 未配置不填假值；本次覆盖不污染共享配置。
7. 覆盖值 0 保留；动态来源缺失明确拒发；并发响应上下文不串用。
8. 调整组合顺序后偏移、长度与 CRC 跟随协议范围计算，旧预览作废。
9. 彩色解析显示各头实例、数组和 Bit 结果；从发送页面即可看到收发及解析。
10. 保存/重启/导入导出后已保存配置仍可用；旧发布版本、旧项目、旧流程可继续运行。
11. 原无人机协议黄金字节保持一致，并完成正常速率的客户端 UDP 回归。
12. 生成 Windows NSIS 安装包，在隔离目录安装并用最终安装版验收。阶段状态据测试结果更新，不以设计文档代替完成证明。

## 9. 决策与仍需实际协议提供的信息

已确定：每信令选择组合、顺序显式、结构和值分离、共享配置显式选择、本次覆盖隔离、当前响应严格关联、歧义不猜测。

实际头 A/B 的字节结构、接收识别特征、长度/校验覆盖范围以用户导入或编辑的协议为准。平台支持配置这些规则，不根据 UI 示例替用户制定业务含义。开发中的组合测试协议仅用于引擎验证，不替代用户的无人机协议。
